CURRENT OFFICIAL SOURCES CHECKED OCTOBER30
Apple: https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion
Apps supporting account creation need an in-app deletion starting point for App
Store submission; full account/data deletion, not just deactivation. Reauthentication
using a code to an existing account contact is permitted. Ordinary apps should not
force email/chat/phone support to complete deletion. We recommend treating this
as applicable to Waist Time; invitation-only onboarding is not an established
exemption, and health journaling does not by itself prove a regulated-industry
exception. Confirm any claimed exception with Apple before relying on it.
Supabase backup docs: https://supabase.com/docs/guides/platform/backups
Provider describes7/14/up-to30-day daily backup windows for Pro/Team/Enterprise,
and recommends off-site exports for Free. These are capabilities, NOT the actual
project's settings. Project-level restore is not an individual-entry service.
Actual plan, backups, PITR, exports and log retention were not accessed or verified.
Supabase authentication: https://supabase.com/docs/guides/auth/auth-email-passwordless
Email OTP is suitable as one component of fresh account authentication. The existing
login UI alone is not a purpose-bound authorization to delete an account.
Supabase user deletion: https://supabase.com/docs/guides/auth/managing-user-data
Deleting Auth is not equivalent to immediate token invalidation or deleting every
related record; existing schema foreign keys also prevent assuming cascade cleanup.
